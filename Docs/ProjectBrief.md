# drift 프로젝트

제작 기준은 사용자가 제공한 `김은수 요구사항 명세서 (1).docx`다.
기존 하이브리드 돛·엔진 시제품 요구사항은 폐기했다.
기존 파일은 실행 경로 밖의 `Backups/before-drift-*.zip`에 보관한다.

## 확정한 범위

- Windows PC, Unity 6000.5.9f1, URP, C#.
- 캐릭터 모델·캐릭터 선택·해금은 구현하지 않는다.
- 모델 없는 테스트용 1인칭 이동·시점·상호작용은 구현한다.
- 방 만들기는 로컬 세션이다. 방 들어가기는 명세서대로 비활성이다.
- 보이스·채팅은 설정과 화면까지 구현한다. 마이크 수집이나 실제 통신은 하지 않는다.
- 모든 플레이어 집결과 공통 퀘스트는 현재 로컬 참가자 1명에 적용한다.
  실제 네트워크 동기화는 이후 멀티플레이 작업에 속한다.

## 구현 구조

- `Assets/Drift/Scripts/DriftState.cs`: 인벤토리, 생존 수치, 튜토리얼 진행 규칙.
- `DriftSettings.cs`: 언어·음량·커뮤니케이션 설정·중복 방지 키 재지정과 저장.
- `DriftApplication.cs`: 로컬 세션과 화면 전환, 상호작용 연결.
- `DriftUI.cs`: uGUI/TMP 메뉴, 설정, HUD, 인벤토리, 로컬 채팅, 라디오 대사.
- `DriftWorld.cs`, `DriftInteractable.cs`: 녹슨 선박의 기능별 구조물과 퀘스트 표시.
- `DriftView.cs`: 캐릭터 모델 없는 테스트 시점.
- `DriftAudio.cs`: 파도·갈매기·경보·무전 잡음·종료음 임시 합성 오디오.
- `Assets/Drift/Editor/DriftProjectSetup.cs`: 최초 임포트 시 시작 장면 생성.

시작 장면은 `Assets/Drift/Scenes/Drift.unity`다. 화면과 월드 객체는 장면의
DriftApplication에서 실행 중 생성된다. Unity의 첫 스크립트 임포트가 끝나면
TMP 기본 리소스와 장면을 만들고 Build Settings를 이 장면으로 교체한다.
이미 생성된 장면은 자동으로 덮어쓰지 않는다. 수동 진입은 `Drift > Create or Open Game`이다.

## 기본 조작

| 동작 | 기본 키 |
|---|---|
| 이동 | W / S / A / D |
| 달리기 | 왼쪽 Shift |
| 점프 | Space |
| 웅크리기 | 왼쪽 Ctrl |
| 인벤토리 | E |
| 상호작용 / 방향타 잡기·놓기 | F |
| 선택 아이템 1개 버리기 | Q |
| 핫바 선택 | 1–8 / 마우스 휠 |
| 생선·물 사용 | 우클릭 / 인벤토리 사용 버튼 |
| 방향타 회전 | 왼쪽·오른쪽 이동 키 |
| 로컬 채팅 화면 | Enter |
| 일시정지 / 뒤로 | Esc |

명세서의 키 10개는 설정에서 재지정할 수 있다. Esc·Enter·Tab·숫자 키는
화면 및 핫바 조작용으로 예약하고, 동작 간 중복 배정을 거부한다.
게임 진행 저장은 명세서 범위가 아니므로 구현하지 않았다. 메뉴로 돌아가면
현재 항해가 끝나고 새 항해는 처음부터 시작된다. 환경설정만 저장된다.

## 플레이 흐름

1. 항해 → 방 만들기 → 항해 시작.
2. 검은 화면이 사라지고 갑판에서 시작한다. 뒤를 돌아 조타실로 이동한다.
3. 조타실 왼쪽 벽의 작업 종이를 F로 읽는다.
4. 갑판 낚싯대를 줍고 낚시 지점에서 생선을 확보한다.
5. 정수기를 점검한다. 연료통을 주워 엔진에 보충한다.
6. 수리 자재를 주워 갑판 손상부를 수리한다.
7. 경보가 울리면 조타실의 라디오와 상호작용한다.
8. 서쪽의 땅을 알리는 대사와 잡음·종료음이 출력된다.
9. 갈매기가 정수기를 고장낸다. 방향타를 서쪽 270°로 맞추고,
   갑판에서 정수기 부품을 찾아 수리한다. 두 작업은 순서와 관계없이 완료할 수 있다.

## 임시 구현 수치와 자산

명세서에 수치가 없는 부분은 코드에서 조정 가능하다. 인벤토리 24칸,
핫바 8칸, 한 묶음 20개, 서쪽 허용 오차 7°, 낚시 재사용 대기 4초다.
환경은 기본 도형 기반 기능 시제품이며 최종 미술 자산이 아니다.
음성 연기·실제 녹음 효과음 대신 임시 합성 효과음을 사용한다.
크레딧은 명세서에 제작진 정보가 없어 추후 등록 안내를 표시한다.
한글 글꼴은 Windows에 설치된 맑은 고딕을 사용하는 TMP DynamicOS 자산이며,
글꼴 파일 자체를 프로젝트에 복사하거나 재배포하지 않는다.

## 검증

`Validation/DriftRules.csproj`는 Unity와 독립적으로 인벤토리와 퀘스트 동작을 검증한다.
실행: `dotnet run --project Validation/DriftRules.csproj`.
Unity 참조 어셈블리에 대한 C# 컴파일과 20개 도메인 동작 테스트를 통과했다.
2026-10-06에 실제 Unity Editor에서 다음 검증을 추가했다.

- `Validation/DriftRuntimeChecks.cs`: 메뉴 버튼, 로컬 방 생성, 언어·음량,
  키 중복·예약 키 거부, 채팅 길이 제한·마크업 방지, 아이템 사용·버리기,
  세션 초기화 등 19개 실행 검사를 통과했다.
- `Validation/DriftPlaythrough.cs`: 실제 장면의 충돌 판정과 가상 키보드 입력을
  사용하여 작업 종이 → 작업 4개 → 무전 → 정수기 파손·수리 → 서쪽 조타의
  11개 검사를 통과했다. 검사에서는 지점 사이를 순간 이동하므로,
  갑판 전체 이동 경로의 수동 플레이 검사를 대신하지 않는다.
- 메뉴·설정·게임 HUD의 1280×720 캡처를 `Docs/Preview`에 저장해 확인했다.
- 검사 도구는 `Assets` 밖에 있어 게임 빌드에 포함되지 않는다.

Windows x64 개발 빌드도 성공했다. 출력은
`Builds/Windows-20261006/drift.exe`이며, 같은 폴더의 데이터·DLL 파일과 함께 실행한다.
빌드 시간은 약 4분 6초, 결과 크기는 약 189 MB다.
보고서의 오류 1건은 120초를 넘은 자동화 요청의 타임아웃이며,
실제 BuildPlayer 결과는 `Succeeded`다. 경고 2건은 Unity 온라인 서비스
프로젝트 연결 미설정과 Player용 Pipeline 비활성 안내다.
현재 범위는 로컬 게임이므로 온라인 서비스 연결은 추가하지 않았다.
자세한 원문 결과는 `Validation/windows-build-result.txt`에 있다.
생성된 실행 파일을 그래픽 활성 상태로 12초간 실행하는 시작 검사를 통과했다.
조기 종료와 주요 시작 예외는 발견되지 않았다. 결과는
`Validation/windows-launch-result.txt`에 있으며, 독립 실행 파일의 전체 수동 플레이나
다른 Windows PC에서의 검증을 대신하지 않는다.

검사 중 발견한 문제와 수정 이유:

1. 항해 종료 후 이전 아이템 알림이 메뉴에 남아, 시작·종료 시 알림을 비운다.
2. 맑은 고딕에 없는 체크 기호가 네모로 표시되어, 완료된 작업은
   `[완료]` / `[Done]` 문구로 표시한다.
3. 자동 검사에서는 임시 가상 키보드와 입력 설정을 사용하고 종료 후 복원한다.
   게임의 창 포커스 상실 시 일시정지 기능은 그대로 유지한다.

반복 세션 초기화, 아이템·채팅 개수 제한, 이벤트 해제와 생성 자산 정리 코드를
검토했다. 장시간 메모리 프로파일링이나 모든 PC 구성 검증을 수행한 것은 아니며,
오류·메모리 누수가 절대 없음을 보증하는 결과는 아니다.
